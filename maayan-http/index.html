HTTP/1.1 — how a request and a response are actually built

Every web page, API call and image download is plain text travelling over the network in a fixed shape: a first line, then headers, then a blank line, then an optional body. The client sends a request, the server sends back a response. That's the whole protocol. Click any colored part below to see what it means.

The request and response share the same skeleton — only the first line differs. A request's first line says what to do (method path version); a response's first line says what happened (version code reason). Everything after is headers, one blank line, then the optional body.
The methods — the verb that says what you want done

The first word of a request. It tells the server your intent:

GET — read, fetch a resource POST — create / submit data PUT — replace a resource PATCH — partly update DELETE — remove HEAD — headers only OPTIONS — what's allowed?

GET and HEAD are safe (read-only). GET, PUT and DELETE are idempotent — repeating them is harmless. POST is neither: submit a form twice and you may create two orders.

The status codes — the 3-digit verdict in the response

The first digit is the whole story:

1xx informational · 2xx success · 3xx redirect · 4xx you (the client) erred · 5xx the server erred.

200OK — here's what you asked for
201Created — your POST made something
301Moved Permanently — use the new URL
304Not Modified — use your cached copy
400Bad Request — malformed
401Unauthorized — log in first
403Forbidden — you can't, even logged in
404Not Found — no such resource
500Internal Server Error — server bug
503Service Unavailable — overloaded/down
Why "1.1"? Persistent connections & keep-alive

HTTP/1.0 opened a fresh connection per request and closed it after the response — expensive, since every connection costs a round-trip to set up. HTTP/1.1 made persistent connections the default (Connection: keep-alive): one connection serves many requests in a row. It also added the mandatory Host header, so one server (one IP) can host many sites — the foundation of modern shared hosting.

On the request

A real round-trip — POST with a body

A login form submission. Note the request now has a body, and Content-Length counts its bytes:

POST /login HTTP/1.1 Host: example.com Content-Type: application/json Content-Length: 44 ␤ {"user":"maayan","pass":"s3cret!"}
HTTP/1.1 200 OK Content-Type: application/json Set-Cookie: session=ab12cd34; HttpOnly ␤ {"ok":true,"name":"Maayan"}
