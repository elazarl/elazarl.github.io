Issue types — not just exceptions

Sentry captures more than crashes:

Error — unhandled exception or explicit capture Performance — slow transaction (N+1 queries, slow DB) Session Replay — video of what the user did before the crash Cron Monitor — missed or failed scheduled job Release Health — crash-free session rate per deploy

All types share the same interface: an SDK call → an event JSON → the pipeline.

How grouping (deduplication) works

Without grouping, one bug crashing 10 000 times would flood your inbox. Sentry's deduplication engine hashes the fingerprint of every event and merges events with the same fingerprint into a single Issue. The counter on the issue shows how many times it fired. You can override the fingerprint in code: scope.set_fingerprint(["my-custom-group"]).

The default fingerprint is derived from: exception type + culprit file/line. Minified JavaScript? Sentry un-minifies it first using source maps.

Alerts — getting paged at the right time

Sentry has two alert types:

Issue Alerts — trigger on conditions: "new issue", "regression", "issue seen > 100×/hour in production". Actions: Slack, PagerDuty, email, webhook.

Metric Alerts — trigger on numeric thresholds: error rate > 5%, p95 latency > 2 s, crash-free sessions < 99.5%. They use a sliding window and a warning + critical level so you get a heads-up before the pager goes off.

Core features — what Sentry gives you

SDKError Capture
One init() call wires up global error handlers. Unhandled exceptions, promise rejections, and explicit captureException() calls are all sent automatically.
ContextUser & Request Context
Attach user ID, email, IP, request URL, and custom tags to every event — so you can filter "show me all errors seen by user X" in one click.
PerformanceDistributed Tracing
Every request becomes a trace: a tree of spans across services, DB queries, HTTP calls. Sentry finds the slowest spans, surfaces N+1 queries, and links traces to errors.
ReleasesRelease Health
Tag each deploy with a version string. Sentry tracks crash-free session rate per release, so you know within minutes if a new deploy is regressing users.
ReplaysSession Replay
A pixel-perfect DOM recording of what the user did before the crash — no PII leakage (inputs are masked). Watch the replay, then jump straight to the error.
WorkflowCode Owners & Routing
Ownership rules (path:src/checkout/* → #frontend) auto-assign issues to the right team. Integrates with GitHub/GitLab so the last committer of the crashing file is notified first.
AISentry Autofix
AI reads the stack trace, browses your codebase, and opens a draft PR with a fix. You review and merge. No context-switching: the root cause analysis happens inside Sentry.

Add Sentry to a PHP app · click any line

require 'vendor/autoload.php'; // Composer autoloader \Sentry\init([ 'dsn' => 'https://<key>@o0.ingest.sentry.io/<project>', 'traces_sample_rate' => 0.2, // capture 20 % of transactions 'send_default_pii' => true, // attach user IP + request data 'release' => 'my-app@1.4.2', 'environment' => 'production',]); \Sentry\configureScope(function (\Sentry\State\Scope $scope) use ($user) { $scope->setUser(['id' => $user->id, 'email' => $user->email]);}); try { $result = risky_operation();} catch (\Throwable $e) { \Sentry\captureException($e); // explicit capture} \Sentry\addBreadcrumb(new \Sentry\Breadcrumb( \Sentry\Breadcrumb::LEVEL_INFO, \Sentry\Breadcrumb::TYPE_DEFAULT, 'cart', 'cart fetched'));

Click any line of code

The PHP SDK (composer require sentry/sentry) works the same way as the others: one init() registers a global error & exception handler, then you enrich the scope and capture explicitly where you want. Framework packages exist for Laravel and Symfony. Click any line to see what it does.
Sentry is open-source and self-hostable. The SDK sends events to ingest.sentry.io (or your own host) asynchronously in a background thread so it never blocks your app. All PII in replays and user context is masked or scrubbed before storage. The event pipeline described here is the same for all SDKs: JS, Python, Go, Ruby, iOS, Android.
