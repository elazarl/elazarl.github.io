gRPC — how it actually works, down to the bytes

gRPC lets one program call a function on another machine as if it were local. You describe the service once in a .proto file; a code generator builds the client & server stubs. On the wire it rides HTTP/2, and the messages are encoded with Protocol Buffers — a compact binary format. Click any colored part to see what it means.

The contract — one .proto file · click any colored part

syntax = "proto3"; service Greeter { rpc SayHello (HelloRequest) returns (HelloReply); } message HelloRequest { string name = 1; ← field number, not a value } message HelloReply { string message = 1; }

The .proto file is the single source of truth — an IDL both sides share. Run the protobuf compiler on it and you get a typed stub in any language. The client calls greeter.SayHello(req); the bytes below are what actually crosses the network.

Why gRPC and not plain REST + JSON?

Binary, not text. Protobuf is far smaller and faster to encode/decode than JSON — no field names on the wire, numbers instead of text.

A real contract. The .proto is typed and versioned. Client and server can't silently disagree about the shape of data; the compiler enforces it. Adding a field stays backward compatible.

Streaming & multiplexing for free. Riding HTTP/2 means built-in multiplexing and long-lived streams in both directions.

The trade-off: it's binary, so you can't just read it with curl, and browsers can't speak raw gRPC (they need gRPC-Web + a proxy). For service-to-service traffic, that's a fine price.

The whole call is one HTTP/2 stream

Headers open it, one or more DATA frames carry the length-prefixed messages, and a final trailers block carries the result code. The status lives at the end, not the start — because the server may only know it failed after streaming a while.

grpc-timeoutdeadline, e.g. 100m = 100 ms
grpc-statusfinal code (trailer). 0 = OK

The payload, byte by byte — HelloRequest{ name: "maayan" } · click any byte

0A 06 6D 61 61 79 61 6E
■ tag■ length■ "maayan" (UTF-8)

Click any byte

Just 8 bytes carry the whole message — no field names, no quotes, no braces. That's the protobuf trick: the .proto already told both sides that field 1 is a string called name, so the wire only needs the field tag, a length, and the raw bytes.
gRPC = RPC over HTTP/2, with Protocol Buffers as the encoding. The bytes shown are exactly what a real Greeter service sends; the byte values are a genuine protobuf encoding of name:"maayan".
